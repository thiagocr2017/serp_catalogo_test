# Carrier Catalog - Requirements

## Proposito

Gestionar transportes como catalogo global reutilizable por clientes, pedidos,
facturas, guias y etiquetas.

## Alcance implementado

- Crear transporte desde Configuracion.
- Editar transporte existente desde Configuracion.
- Listar transportes activos por nombre.
- Exponer transportes por la API publica de Configuracion.
- Permitir que Clientes seleccione un transporte preferido por defecto.

## Campos iniciales

- `name`
- `phone`
- `address`
- `contact_name`
- `notes`
- `is_active`
- `version`

## Reglas

- El nombre es obligatorio.
- No puede haber dos transportes con el mismo nombre normalizado.
- Sales no escribe transportes directamente; consume el catalogo publico de
  Configuracion.
- El transporte preferido de cliente es un default, no una decision obligatoria.
- Pedido/factura podra sobrescribir el transporte del cliente sin cambiar el
  default.

## Fuera de alcance actual

- Costos por caja.
- Zonas/rutas.
- Horarios.
- Datos fiscales del transporte.
- Desactivacion desde UI.
- Agrupacion de guia/ruta.
