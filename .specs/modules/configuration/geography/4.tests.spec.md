# Geografía de Clientes - Contrato de Pruebas

## 1. Pruebas de Base de Datos (pgTAP)

**Archivo**: `supabase/tests/database/geography_catalogs_test.sql`

### Contratos de Estructura y Tablas
- `countries`:
  - Clave primaria `code` de tipo `text`.
  - Columna `name` no nula.
  - Columna `is_active` booleana no nula.
  - Registro inicial `'CR'` ('Costa Rica') presente y activo.
- `administrative_areas`:
  - Clave foránea `country_code` apuntando a `countries(code)`.
  - Índice de unicidad `(country_code, lower(btrim(name)))`.
  - Las 7 provincias de Costa Rica (San José, Alajuela, Cartago, Heredia, Guanacaste, Puntarenas, Limón) precargadas.
- `cities`:
  - Clave foránea `country_code` apuntando a `countries(code)`.
  - Índice de unicidad `(country_code, lower(btrim(province_name)), lower(btrim(name)))`.
  - Cantones y distritos oficiales del INEC precargados para Costa Rica.
- `customers`:
  - Columna `country_code text not null default 'CR' references public.countries(code)`.
  - Columna `city text`.

### Contratos de Privilegios y Seguridad (RLS)
- RLS activado en `countries`, `administrative_areas` y `cities`.
- Permiso `SELECT` concedido a `authenticated` y `anon`.
- Permisos directos `INSERT`, `UPDATE`, `DELETE` revocados a `authenticated` y `anon`.

### Contratos de Funciones y Procedimientos (RPC)
- `create_customer` y `update_customer` aceptan 21 parámetros incluyendo `p_country_code` y `p_city`.
- Wrappers con 19 parámetros mantienen compatibilidad total con consumidores heredados.
- Inserción con ciudad conocida: persiste el cliente sin duplicar entradas en `cities`.
- Inserción con ciudad desconocida/nueva: persiste el cliente y añade automáticamente el registro a `cities` (autoaprendizaje).
- Idempotencia: invocar la actualización con la misma ciudad nueva no genera errores por colisión de índice único.

## 2. Pruebas de Frontend y Validación (Flutter)

**Archivos**:
- `test/modules/sales/presentation/customers_form_validation_test.dart`
- `test/modules/sales/presentation/customer_profile_page_test.dart`
- `test/core/architecture/module_boundary_test.dart`

### Casos de Prueba Requeridos
1. **Formulario - Selección y Guardado de Geografía**:
   - Abrir el formulario de nuevo cliente.
   - Completar nombre fiscal.
   - Seleccionar provincia 'Cartago' desde el desplegable oficial.
   - Ingresar o seleccionar ciudad 'Paraíso'.
   - Guardar el cliente.
   - Verificar que la API reciba `countryCode: 'CR'`, `province: 'Cartago'` y `city: 'Paraíso'`.
2. **Formulario - Compatibilidad con Pruebas Existentes**:
   - El formulario debe mantener abiertos los campos con error de validación cuando falte el nombre o datos obligatorios.
   - Las pruebas de clientes existentes deben actualizar y persistir la información sin regresiones.
3. **Perfil - Renderizado de Ubicación**:
   - `CustomerProfilePage` debe renderizar visualmente las etiquetas de País, Provincia y Ciudad / Distrito cuando estén presentes.
4. **Frontera de Módulos**:
   - `test/core/architecture/module_boundary_test.dart` debe verificar que `sales` interactúa con los catálogos territoriales únicamente a través de `configuration_module.dart` / `ConfigurationApi`.
