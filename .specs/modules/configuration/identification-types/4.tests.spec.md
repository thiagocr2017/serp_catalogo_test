## Cobertura obligatoria

- Crear tipo vacio y validar que no se guarda (codigo y nombre).
- Crear tipo valido y verificar que el comando llega a la API publica con
  codigo y nombre.
- Renombrar y desactivar un tipo existente, verificando id, nombre,
  `isActive` y `expectedVersion` enviados.
- Alta idempotente: repetir el mismo `command_id` no duplica la fila.
- Payload distinto con el mismo `command_id` se rechaza.
- Codigo duplicado con otro comando se rechaza.
- Edicion con `expected_version` viejo se rechaza (`VERSION_CONFLICT`).
- Edicion de un tipo inexistente se rechaza (`NOT_FOUND`).
- Tipo desactivado no puede asignarse a un cliente
  (`IDENTIFICATION_TYPE_INACTIVE`).
- Privilegios: `authenticated` puede ejecutar las RPC y no puede insertar en
  la tabla de comandos ni en la tabla.
- Auditoria registrada para CREATE, UPDATE (nombre) y DEACTIVATE.
- Los 6 tipos precargados siguen intactos.

## Criterio de listo

El catalogo no se considera listo si solo crea: debe poder renombrar,
desactivar, reactivar y demostrar que un tipo desactivado ya no entra en
clientes nuevos sin romper a los existentes.
