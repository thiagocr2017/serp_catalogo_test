# One-Time PIN Approval - Requirements Draft

## Proposito

Permitir aprobaciones puntuales de acciones restringidas sin cambiar
permanentemente la configuracion del cliente o del documento.

## Caso inicial

Autorizar una factura a credito para cliente contado, o autorizar una factura de
cliente de credito cuando saldo activo + factura alcanza/supera el limite de
credito.

## Reglas

- El PIN lo genera un usuario autorizado.
- El PIN es aleatorio.
- El PIN sirve para un solo uso.
- El PIN debe quedar auditado: quien lo genero, para que cliente/documento,
  fecha, dispositivo y resultado.
- El PIN no cambia al cliente contado a credito de forma permanente.
- Si se necesita cambiar permanentemente de contado a credito, eso se hace
  editando el cliente con permisos adecuados.

## Preguntas pendientes

Resueltas el 2026-10-03 (ver
`../sales/customer-management/0.open-questions.md`, decisiones 25, 26 y 27):

- ~~Duracion del PIN antes de expirar.~~ **Decision 26:** el PIN **no caduca por
  tiempo**: se consume al usarse. Si la implementacion no puede garantizar un
  unico uso, el respaldo es caducar a los **10 minutos**.
- ~~Si el PIN autoriza un documento exacto, un cliente, un monto maximo o una
  accion especifica.~~ **Decision 27:** autoriza **un cliente y un monto
  maximo**. No una factura concreta.
- ~~Que usuarios/roles pueden generarlo.~~ **Decision 25:** los roles
  **superadministrador** y **gerente**. Nota: hasta que exista Autenticacion la
  identidad es el equipo, y solo el superadministrador es verificable hoy.

Siguen **genuinamente abiertas**, porque no entraban en el bloque de 23:

1. Longitud y formato del PIN (digitos, alfanumerico, con letras).
2. Si el PIN se muestra en pantalla, se imprime o se comparte verbalmente.
