# Inventory Document Form - Tests

## Estado actual

Parcial. `test/modules/inventory/presentation/inventory_document_form_page_test.dart`
verifica el rechazo de linea sin producto sin llamar la API y la confirmacion
UI de un ajuste con payload correcto, seguido de navegacion al detalle. Esas
pruebas usan una API fake y no demuestran persistencia PostgreSQL.

## Cobertura obligatoria

- Rechazar documento sin lineas.
- Rechazar linea sin producto.
- Rechazar cantidad invalida.
- Confirmar documento valido.
- Verificar creacion atomica de documento y movimientos.
- Verificar que un error de persistencia no deja movimientos huerfanos.
- Verificar auditoria cuando aplique.
- Verificar que salir con cambios pide confirmacion y que cancelar la
  confirmacion mantiene el formulario abierto.
- Verificar que guardar correctamente abre el detalle, cuyo retorno lleva al
  indice `/inventory/documents`.
- Verificar traslado entre ubicaciones, bloqueo de cantidad superior al saldo,
  guardado/confirmacion de borrador y error de persistencia conservando el
  formulario.
- Verificar que `Guardar como borrador` conserva líneas y destinos sin crear
  movimientos hasta que se despache desde la lista.
- Agregar prueba de integracion contra Supabase local que confirme el
  documento, relea lineas/movimientos y compruebe los saldos afectados.
- E2E local: abrir desde Movimientos, confirmar un ajuste positivo y verificar
  detalle, documento, linea, movimiento, saldo y retorno al indice.

## Criterio de listo

El formulario no se considera listo hasta tener prueba de UI y de integracion
que demuestren confirmacion real, validaciones negativas y atomicidad.
