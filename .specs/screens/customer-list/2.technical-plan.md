# Customer List - Technical Plan

## Archivos

- `lib/modules/sales/presentation/pages/customers_page.dart`

## Implementacion

- Mantener la pantalla dentro del modulo `sales`.
- Usar `customersProvider` como fuente actual.
- Filtrar localmente mientras no exista busqueda server-side.
- Normalizar la busqueda con terminos separados por espacios.
- Mostrar informacion densa y escaneable en filas/cards simples.
- Mostrar una barra operativa al inicio de la lista con busqueda, filtros,
  contador de resultados y accion secundaria `Limpiar filtros` solo cuando
  existan filtros activos.
- Mantener cards compactas como layout actual; preparar el contrato para una
  tabla densa en desktop amplio sin bloquear estos quick wins.
- Diferenciar dos estados vacios:
  - sin clientes: CTA `Crear primer cliente`;
  - sin resultados: CTA `Limpiar filtros`.
- Agregar `Semantics`, labels o tooltips a crear cliente, busqueda, filtros,
  limpiar filtros y cards clicables.

## Compatibilidad

No cambia contratos de base de datos ni APIs. La busqueda es visual/local y
puede reemplazarse por consulta paginada cuando el volumen de clientes lo
requiera.

## Decision UX

La lista es una pantalla operativa. Debe ayudar a encontrar y abrir clientes,
no concentrar todo el historial comercial. El historial y alertas pertenecen al
perfil/display de cliente.

## UX/UI

Principio rector: la lista encuentra. Por eso el control principal es buscar y
seleccionar; crear cliente es secundario pero visible, y limpiar filtros solo
aparece cuando ayuda a recuperarse de un resultado vacio o reducido.
