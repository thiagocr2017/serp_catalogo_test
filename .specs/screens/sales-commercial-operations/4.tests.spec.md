# Sales Commercial Operations - Test Spec

## Cobertura obligatoria

- `test/modules/sales/presentation/sales_document_form_page_test.dart` cubre
  formularios operativos y bloqueo de devolucion, ademas del payload de
  cotizacion.
- Cotizacion: no ejecutar API si falta cliente o linea/precio/cantidad valida;
  creacion valida conserva el payload.
- Pedido: cliente, al menos una linea, bodega y ubicacion antes de persistir.
- Factura: al menos una linea, cliente y bodega (sin pedir ubicación); el RPC
  distribuye movimientos por las ubicaciones con stock disponible de esa
  bodega; cancelacion exige motivo.
- Devolucion: mostrar estado no disponible; no consultar elegibilidad ni
  ejecutar una mutacion desde la pantalla de inicio.
- Los accesos contextuales a devolucion preservan retorno, y al seguirlos
  informan el bloqueo en lugar de sugerir una operacion utilizable.
- Un error/carga del resumen de documentos pendientes en el perfil no se
  presenta como una lista vacía; el desglose coincide con documentos del
  cliente y sus estados reales.
- Las acciones de devolución desde lista y detalle de facturas, y desde el
  perfil del cliente, precargan factura y conservan `returnTo`; los pedidos
  abiertos desde pendientes se filtran por cliente y ofrecen volver al perfil.
- Consignacion: cliente, lineas, bodega y ubicacion; devolucion parcial no
  supera cantidad pendiente.
- En cada formulario, error de persistencia mantiene formulario y borrador.
- Cada lista presenta loading/error/empty/data y CTA de crear.
- Devolucion y consignacion muestran detalle cargado, error y no encontrado.
- Detalle vuelve a su lista y perfil del cliente vuelve al mismo detalle.
- El detalle no presenta acciones financieras o transiciones no soportadas.
- Navegar fuera de formulario sucio ofrece continuar editando o descartar.

## Cobertura pendiente

- Las pruebas de payload negativo/positivo para pedido y consignacion, ademas
  de acciones de estado de algunas listas, siguen pendientes.
- Devolucion permanece fuera de operacion hasta completar la cobertura pgTAP
  definida en el contrato de base de datos del modulo.

## Criterio de listo

Cada comando visualizado debe tener prueba de payload valido y al menos un caso
negativo sin persistencia. No se declara lista una accion que no tenga comando
publico correspondiente.
