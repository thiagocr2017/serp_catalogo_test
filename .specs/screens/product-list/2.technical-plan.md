# Product List - Technical Plan

## Ordenamiento por Defecto y Sincronización del Catálogo

- Ajustar la consulta principal en el `ProductDataSource` para incluir un `ORDER BY category.catalog_sort_order ASC, product.catalog_sort_order ASC, product.name ASC`.
- Asegurar que al modificar el orden en el componente de Catálogo PDF, los cambios se repliquen atómicamente a los campos `catalog_sort_order` en las tablas `products` y `categories`.
- Si las categorías y productos no tienen el campo `catalog_sort_order`, se deberá crear la respectiva migración SQL en PostgreSQL para agregarlo como `INTEGER NOT NULL DEFAULT 0`.

## Miniaturas en Lista

- Compartir `ProductImageService.getLocalThumbnail` entre tabla y cuadrícula.
- Guardar junto a la miniatura la URL de origen y regenerarla cuando la fuente
  cambie. El reemplazo de imagen también elimina ambos archivos de caché.
- No usar `Image.network` como fallback simultáneo mientras se solicita la
  miniatura local; mostrar progreso y un estado de error si no carga.
- La busqueda remota usa `effectiveSearchQuery` desde tres caracteres y aplica
  150 ms de debounce; al borrar por debajo del umbral, limpia inmediatamente
  el termino y conserva los demas filtros.
- Durante una consulta remota se conservan las filas anteriores y se muestra
  una barra de progreso lineal hasta reemplazarlas por el resultado nuevo.
- En la lista, reactivar usa `SaveProduct.update` con el producto completo y
  `isActive: true`; desactivar conserva la RPC existente. Ambos caminos
  confirman, muestran progreso y refrescan manteniendo el filtro seleccionado.
