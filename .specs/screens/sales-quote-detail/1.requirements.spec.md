# Detalle de Cotizacion - Requisitos

## Proposito

Permitir consultar y operar una cotizacion persistida desde su lista y desde el
perfil del cliente, manteniendo el estado comercial visible y una salida clara
al contexto que abrio el documento.

## Requisitos

- La lista indice permite buscar sin distinguir mayusculas/minusculas por
  numero, cliente, estado, codigo SKU, producto, presentacion, moneda y notas.
- La lista permite filtrar por estado y combinar ese filtro con la busqueda;
  limpiar busqueda y filtro restaura todos los resultados.
- Cada resultado muestra codigo de moneda guardado, total y estado semantico;
  nunca asume simbolo `$` para documentos de distintas monedas.
- Si los criterios no encuentran resultados, se muestra estado vacio distinto
  de una lista sin cotizaciones registradas.
- Cada fila de `/sales/quotes` tiene accion visible para abrir
  `/sales/quotes/:id`; menu overflow no reemplaza la accion de apertura.
- El menu overflow debe permanecer dentro del ancho disponible; la fila debe
  permitir abrir el detalle sin apuntar al menu secundario.
- El detalle muestra cliente, numero, estado, fechas, notas, moneda, lineas,
  cantidad/presentacion snapshot, precio, descuento y totales.
- Cliente enlaza al perfil, y el perfil vuelve al mismo detalle.
- Cotizacion en borrador ofrece editar cabecera y lineas; cualquier otro estado
  es de solo lectura.
- Borradores aparecen en la pestana Cotizaciones del perfil de cliente con chip
  `Borrador`; incluir todos los estados pertinentes y no etiquetarlos como
  cotizaciones activas genericas.
- Desde lista, detalle y perfil se permiten las transiciones que autoriza el
  API: borrador -> enviada/aceptada/rechazada; enviada -> aceptada/rechazada.
- Mostrar acciones solo si la transicion esta permitida por el estado actual.
- Un documento abierto desde cliente conserva `returnTo`/contexto y ofrece
  `Volver al cliente`; una apertura desde lista ofrece `Volver a cotizaciones`.
- Cambios de estado exitosos invalidan listado, detalle y datos del perfil; un
  error conserva pantalla/estado previo e informa al usuario.
- Edicion de borrador actualiza cabecera y lineas en una RPC transaccional; el
  servidor rechaza estados diferentes de `DRAFT`.
- Aceptar una cotizacion no crea ni despacha documentos implicitamente. Tras
  aceptar, ofrecer elegir el siguiente documento: pedido/hoja de bodega en
  borrador o factura en borrador; cada documento mantiene vinculo de origen.
- Stock, punto de reorden y alertas de inventario son informacion interna de
  cotizacion; nunca se imprimen ni se incluyen en el PDF/representacion para el
  cliente.

## Criterios de aceptacion

1. Tocar la fila/accion de una cotizacion en lista abre el ID seleccionado.
2. El perfil del cliente lista borradores, estado visible y total.
3. Acciones de aceptar/rechazar/marcar enviada actualizan el estado via API.
4. Accion no disponible para estado terminal no se muestra.
5. Retorno vuelve al origen contextual, incluso tras completar una accion.
6. Stock bajo/agota se distingue internamente y no aparece en salida imprimible.
