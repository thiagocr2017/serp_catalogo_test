## Dependencias permitidas

La pantalla pertenece a `sales` y debe usar APIs publicas si requiere datos de
otros modulos.

## Navegacion

- Crear cliente usa ruta `/sales/customers/new`.
- Editar cliente usa ruta `/sales/customers/:id/edit`.
- La lista de clientes no abre el formulario completo en modal.
- Los modales dentro del formulario quedan reservados para acciones puntuales,
  como confirmar desactivacion o crear catalogos auxiliares rapidos.

## Riesgos

- Persistir contactos invalidos.
- Perder contactos al editar.
- Permitir operaciones sobre clientes inactivos sin regla explicita.
- Convertir el formulario en una pantalla demasiado grande y lenta de usar.
- Mezclar configuracion global, catalogos y datos de cliente en una sola UI.
- Duplicar reglas fiscales que deberian vivir en documentos/facturacion.
- Crear dependencias directas desde ventas hacia modulos internos de pagos,
  inventario o configuracion.

## Enfoque UI/UX recomendado

- Usar pagina completa o panel de edicion con secciones para crear/editar.
- Seccion "Datos del cliente" ordenada por: Nombre fantasía, Nombre fiscal, Tipo de documento, Número de documento, Actividad económica (CIIU con formato numérico/decimal), Teléfono, Correo principal, Correos en copia.
- Seccion "Crédito y documentos": Documento habitual (`TICKET`, `E_INVOICE`, `ASK_EACH_TIME`). Si es `E_INVOICE`, se renderiza `SwitchListTile` activado y deshabilitado (`onChanged: null`); si es distinto, se oculta completamente.
- Mantener acciones primarias fijas: Guardar, Cancelar, Desactivar.
- Mostrar errores junto al campo y un resumen superior cuando haya multiples.

## Cambios de datos esperados

Crear migraciones para:

- Nombre fantasia.
- Tipo de identificacion.
- Tipo de cliente y dias de credito.
- Preferencia factura electronica/tiquete.
- Pais, provincia/estado, ciudad.
- Fecha de registro.
- Motivo de desactivacion.
- Categoria manual e inteligente.
- Multiples emails de documentacion.
- Fecha de cumpleanos en contactos.
- Preferencia/configuracion de envio.

No implementar todos los campos en una sola migracion si las decisiones de
negocio siguen abiertas.
