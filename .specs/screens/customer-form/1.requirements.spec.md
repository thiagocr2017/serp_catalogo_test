# Customer Form - Requirements

## Proposito

Gestionar clientes y contactos comerciales desde Ventas, con validaciones de
datos principales y limite de contactos.

## Alcance actual

- Crear cliente valido.
- Cargar cliente existente.
- Actualizar cliente.
- Desactivar cliente.
- Guardar contactos asociados.
- Validar datos invalidos y limite de contactos.
- Seleccionar transporte preferido desde el catalogo global de Configuracion.

## Alcance objetivo

- Validar email principal con formato de email.
- Capturar nombre fiscal y nombre fantasia.
- Capturar tipo de identificacion y numero de identificacion.
- Capturar tipo de cliente: contado o credito.
- Capturar dias de credito cuando el cliente es de credito.
- Capturar preferencia de documento: factura electronica o tiquete.
- Capturar datos geograficos: pais, provincia/estado y ciudad.
- Capturar fecha de registro.
- Capturar motivo obligatorio al desactivar.
- Capturar categoria manual de cliente.
- Mostrar categoria inteligente calculada, sin exponer la formula.
- Capturar contactos con fecha de cumpleanos.
- Permitir varios correos de documentacion/facturacion.
- Capturar preferencia de envio cuando este definida por la spec de envio.
- Capturar transporte preferido del cliente como default para pedidos/facturas.

## Escenarios

### Crear cliente valido

Given el usuario completa los datos obligatorios del cliente  
When guarda el formulario  
Then el cliente queda disponible en Ventas.

### Rechazar contactos invalidos

Given el usuario agrega una fila de contacto sin nombre, telefono o cargo  
When intenta guardar  
Then el formulario muestra errores y no persiste datos invalidos.

### Contactos opcionales

Given el cliente no necesita contactos registrados  
When el usuario guarda sin filas de contacto  
Then el cliente se guarda sin exigir datos de contacto.

### Cliente sin limite de credito

Given el usuario deja vacio el limite de credito al crear o editar  
When guarda el cliente  
Then el limite se persiste como 0 y no como NULL.

### Telefonos

Given el formulario solicita telefono de cliente o contacto  
When el usuario escribe el dato  
Then el codigo de pais se captura separado del numero local.

Given el usuario escribe un numero local  
When intenta guardar  
Then el numero local debe tener al menos 8 digitos y aceptar solo numeros.

Given un telefono se muestra al usuario  
When existe codigo de pais y numero local  
Then se muestra con el formato `+506 2435-7658`.

### Email principal

Given el usuario escribe email principal  
When intenta guardar  
Then el email debe tener formato valido o el formulario muestra error y no
persiste el cliente.

Given el usuario deja el email principal vacio  
When guarda  
Then el campo se persiste como vacio/null si no es obligatorio para el tipo de
documento seleccionado.

### Nombre fantasia

Given el usuario registra un cliente  
When escribe nombre fantasia  
Then el nombre fantasia se usa para busqueda y visualizacion interna, pero no
reemplaza el nombre fiscal en documentos.

### Tipo de identificacion

Given el usuario registra identificacion  
When selecciona tipo de identificacion  
Then el tipo debe existir en un catalogo gestionable y el numero se guarda
asociado a ese tipo.

### Tipo de cliente y credito

Given el tipo de cliente es contado  
When se intenta crear una factura a credito  
Then el sistema debe bloquear la operacion.

Given el tipo de cliente es credito  
When se guarda el cliente  
Then debe existir cantidad de dias de credito y limite de credito segun reglas
definidas.

### Documento fiscal preferido

Given el cliente requiere factura electronica  
When se emite documento de venta  
Then la factura debe usar los datos fiscales del cliente.

Given el cliente requiere tiquete  
When se emite documento de venta  
Then no se debe exigir la misma informacion fiscal que para factura, salvo que
la regulacion local lo requiera.

### Geografia

Given el usuario selecciona pais y provincia/estado  
When escribe ciudad  
Then el campo sugiere ciudades ya usadas que coinciden con el texto.

Given la ciudad escrita no existe  
When guarda el cliente  
Then la ciudad nueva queda disponible como sugerencia futura.

### Desactivacion

Given el usuario desactiva un cliente  
When confirma la accion  
Then debe registrar motivo obligatorio y conservar historial del cliente.

### Correos de documentacion

Given el cliente requiere copias a varios correos  
When el usuario agrega destinatarios  
Then cada correo debe validarse individualmente y quedar clasificado por uso
si aplica: facturacion, documentos, comercial u otros.

### Transporte preferido

Given existe un catalogo de transportes activos en Configuracion  
When el usuario selecciona transporte preferido en el cliente  
Then el cliente guarda `preferred_carrier_id`.

Given el usuario no selecciona transporte preferido  
When guarda el cliente  
Then el cliente queda sin transporte default y pedidos/facturas deberan pedir o
inferir transporte por otro flujo.

## Fuera de alcance

- Implementacion de documentos de venta.
- Envio real de facturas electronicas o emails.
- Calculo definitivo de top inteligente de clientes.
- Impresion de guias/rotulos de envio.
