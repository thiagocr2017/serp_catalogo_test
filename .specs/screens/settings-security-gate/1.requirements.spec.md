# Puerta de seguridad de Configuracion - Requisitos

- Mientras el bootstrap de Supabase Auth no este implementado y verificado, la
  pantalla no ofrece controles para purgar datos ni cambiar a `PRODUCTION`.
- La pantalla explica el modelo aprobado sin registro abierto y que la primera
  cuenta superadministradora se vinculara mediante Supabase Auth.
- El estado `isSuperAdmin` legado basado en dispositivo no habilita acciones.
- Las llamadas del cliente a purga deben fallar sin invocar la RPC.

## Aceptacion

- Aun si la configuracion simulada indica superadministrador, no hay boton de
  purga/transicion mientras el gate permanezca cerrado.
- Una llamada programatica a la operacion destructiva del repositorio falla
  localmente; la base tambien deniega `EXECUTE` a `PUBLIC`, `anon` y
  `authenticated`.
